# SOFIX VPN 0.8 Beta — согласованное ТЗ и план приёмки

**Статус: объём согласован, реализация НЕ начата.**
**Дата фиксации:** 20.10.2026.
**Правило:** этот документ не запускает сборку APK, не меняет production VPN, подписки, правила пользователей или устройства. Релиз 0.8 будет отдельно, после реализации и тестов. Текущая стабильная для теста бета — 0.7.

## Цель и точный объём

Выпускаем пакет из семи взаимосвязанных функций в **одном интеграционном релизе**, а не по одной APK за баг:

1. Умное раздельное туннелирование с российским шаблоном.
2. Ручные списки «Всегда через VPN» и «Всегда напрямую».
3. Режимы маршрутизации и их переключение.
4. Достоверная диагностика состояния VPN и интернета.
5. Остаток подписки на главном экране.
6. Подписанные обновляемые списки доменов без нового APK.
7. Изолированный тестовый сценарий первого запуска.

Android остаётся VPN-клиентом. Подписка, деньги, платежи и устройства — через Mini App. Отдельное правило **для установленного приложения** (per-app split) и оплату в APK не включаем в 0.8, но архитектуру не закрываем для следующего этапа.

### Подтверждённая база

- Android: Kotlin/Compose, v2rayNG + Xray, Android VpnService; Android обновляется с постоянной подписью SOFIX.
- У Xray уже есть упорядоченные маршруты direct/proxy и модель RulesetItem: domain/ip/process/outboundTag. CoreConfigManager добавляет включённые правила в список; порядок имеет значение.
- Есть пресет custom_routing_white_russia с geosite:category-ru, geoip:ru. **Не включать этот пресет без переработки**: российский IP и зона .ru не гарантируют доступность без VPN.
- Для статуса устройства есть аутентифицированный GET /mobile/api/me (в ответе state и expires_at); для гостя — GET /mobile/api/trial/status. Android не получает Telegram initData из Mini App.
- На OPPO A54 5G / ColorOS 13 уже подтверждены автообновление APK, восстановление соединения после Wi-Fi и автозапуск после reboot. Не ломать эти сценарии.

## 1. Три режима маршрутизации

| Режим | По умолчанию для неизвестного публичного адреса | Что направляется напрямую | Что через VPN |
|---|---|---|---|
| Умный (режим по умолчанию для новых установок после проверки) | VPN | Локальная сеть, российский шаблон, явно добавленное пользователем «без VPN» | Известные ограниченные ресурсы, всё неизвестное, личный список «через VPN» |
| Весь интернет через VPN | VPN | LAN/служебные адреса + явно заданный список «без VPN» | Остальные публичные адреса |
| Только выбранные сайты через VPN | Напрямую | Все, кроме явных исключений | Только список «всегда через VPN» |

**Важно:** «Весь интернет через VPN» не значит «включить kill switch» или «заблокировать LAN». Системную настройку Android «Блокировать подключения без VPN» самостоятельно не включаем. «Только выбранные сайты» НЕ применяет автоматически российский список ограничений: название режима должно соответствовать поведению.

### Российский умный шаблон

- Суффиксы .ru и .рф (нормализация кириллицы/IDN в ASCII/Punycode), аккуратно проверенный набор российских сервисов на других зонах и geosite:category-ru — direct.
- Сначала исключения, затем список ограниченных ресурсов: если заблокированный сайт имеет домен .ru, он идёт в VPN.
- Неизвестные иностранные и неизвестные публичные IP — VPN. При отсутствии надёжного имени домена автоматическое направление напрямую только по geoip:ru **не используется**.
- Нельзя по одной зоне, стране IP, TLS SNI или обратному DNS безошибочно понять, заблокирован ли ресурс в РФ. Учитываем CDN, ECH, DoH/DoT, IP-only и приложения с собственным DNS.
- В конфигурации не должно возникать пути, по которому «Всегда через VPN» самопроизвольно превращается в direct при ошибке DNS, маршрута или потере сервера.

## 2. Приоритеты и конфликтная логика

Правила работают как компилируемая таблица приоритетов, а не как набор разрозненных пользовательских переключателей:

1. Защищённые системные правила: loopback, локальная сеть, служебные адреса VPN, предотвращение loop, служебный DNS. Из обычного интерфейса не переопределяются.
2. Личные исключения пользователя; внутри них — **наиболее точное совпадение**: точный хост выше правила на родительский домен, длинный суффикс выше короткого.
3. Подписанный список известных ограниченных доменов → proxy (в «Умном»).
4. Российский шаблон → direct (в «Умном»).
5. Остальное → fallback выбранного режима.

Примеры конфликтов:

| Условие | Результат |
|---|---|
| blocked.ru в автоматическом списке и одновременно домен .ru | VPN |
| blocked.ru вручную добавлен «Всегда напрямую» | Direct; показать предупреждение, что сайт может не открыться |
| foreign.com вручную «Всегда через VPN» в режиме «Только выбранные» | VPN |
| parent.ru → напрямую и video.parent.ru → VPN | video.parent.ru через VPN, другие поддомены parent.ru напрямую |
| Один и тот же нормализованный домен в обоих ручных списках | Не сохранять конфликт. Показать «Переместить в другой список» / «Отмена» |
| Два одинаково конкретных правила, но разные маршруты | Ошибка валидации/явное исправление, не зависеть от порядка сохранения |
| Пропала/сломалась новая подборка автоматических правил | Последняя проверенная версия, личные правила не меняются |

**Миграция:** текущие экспертные маршруты из MmkvManager не удалять. При первом включении нового SOFIX Smart сохранять их неизменный снапшот и отделять SOFIX-managed записи от ранее настроенных вручную. Конфликт экспертного правила с новым шаблоном — уведомление, безопасный предварительный просмотр и выбор, а не молчаливое удаление. Должна быть функция возврата к прежнему набору.

### Добавление ручного домена

- Принимать имя сайта или URL; извлекать host без пути, порта и схемы; lowercase, IDN → ASCII, убрать завершающую точку.
- Обычно правило охватывает сам host и все его поддомены. При добавлении показывать «Будет действовать для example.ru и его поддоменов».
- Отклонять пустые и невалидные имена, произвольные wildcard, управляющие символы, IP/CIDR в поле «домен», широко действующие Public Suffix (например, com, ru, *.ru). IP/CIDR — только в техническом режиме с отдельной проверкой.
- Проверять канонические дубли, автоматически предлагать перенос между списками, не создавать одинаковые записи.
- Пользователь может искать, переименовать пометку, удалить, посмотреть почему правило сработало и при необходимости отменить действие.
- Изменение становится активным только после успешной компиляции нового Xray config. Если нужна перезагрузка туннеля, обозначить её; при ошибке — откатить старый рабочий набор.
- Не менять конфигурацию Xray на каждый ввод символа. Сохранять и применять завершённое действие.

## 3. UI: Настройки → Раздельное туннелирование

Нативный экран в стиле SOFIX (без технических outboundTag или JSON). Последовательность:

1. Заголовок и одна понятная фраза про разделение российского и зарубежного трафика.
2. Три крупные карточки-режима: «Умный — рекомендуется», «Весь интернет через VPN», «Только выбранные сайты». Краткое описание последствий и ясный активный выбор.
3. Карточка «Всегда через VPN»: список, счётчик и кнопка добавления.
4. Карточка «Всегда напрямую»: список, счётчик и кнопка добавления.
5. «Проверить правило для сайта»: ввести адрес, локально рассчитать направление и показать основание: «Личное исключение», «Список ограниченных», «Российский ресурс», «Режим по умолчанию».
6. Дата и версия правил, обновление вручную, статус фоновой проверки.
7. «Восстановить рекомендованные настройки» с подтверждением. Личные исключения по умолчанию **сохранять**; полная очистка отдельным осознанным действием.

Обычному пользователю не показывать правила IP/портов, технические секции и примитивы Xray. Эти параметры остаются в существующем меню «Расширенные настройки» без стирания пользовательской конфигурации.

## 4. DNS, IPv6 и сетевые исключения (обязательные, а не «после релиза»)

- DNS должен согласовываться с принятым маршрутом: VPN-домены разрешаются через защищённый удалённый resolver, прямые — разрешённым локальным/региональным. Проверять утечки DNS и не отправлять запросы чувствительных proxy-доменов открытому DNS провайдера.
- Изучить текущий режим Android Private DNS и поведение VpnService, Xray DNS, FakeDNS/sniffing. Домен может быть неизвестен при ECH, DoH или работе только по IP; не рисовать пользователю фиктивную точность.
- Проверять IPv4, IPv6, dual-stack, NAT64/DNS64; локальная сеть и loopback не должны неожиданно уходить через зарубежный сервер.
- Проверить QUIC/HTTP3 и UDP/443: не блокировать весь QUIC просто ради упрощения маршрутизации.
- Проверять маршруты по фактическому пути соединения (proxy/direct) и состоянию DNS, а не по одному HTTP 200.
- Смена Wi-Fi, пропажа сети, captive portal, reboot, Always-on VPN, battery saver и временная потеря сервера должны сохранять правильный приоритет правил и работоспособный last-known-good.

## 5. Правила доменов обновляются независимо от APK

Отдельный *версионированный пакет правил SOFIX* (не клиентская подписка): версия формата и набора, дата выпуска, минимальная поддерживаемая версия клиента, срок актуальности, списки ограниченных и российских доменов, подпись и хеш.

**Безопасность:** HTTPS + подпись Ed25519 содержимого/манифеста (публичный ключ в APK, приватный вне публичного GitHub и интернет-сервера). Один SHA-256 по HTTPS не защищает при компрометации источника. Предусмотреть контролируемую смену публичного ключа в последующей APK.

Обязательные свойства загрузчика:

- Строгая схема JSON/данных, верхние пределы размера, количества и длины записей; не допускать выполнения кода, правки VPN-подписки, оплаты или адресов серверов через этот канал.
- Staging → проверка корректности/изменений → подписание → production; контрольные тесты и возможность откатить серверный пакет.
- Проверка после запуска и восстановления сети, затем разумно редко (например, раз в сутки); никаких постоянных запросов или прерывания подключения ради проверки.
- Last-known-good хранится локально. При сетевой ошибке, неправильной подписи, неподдерживаемом формате или ошибке Xray — не трогать работающие правила.
- Сначала compile/validation нового пакета, затем атомарное применение; сохранять предыдущий пакет для rollback после сбоя.
- Нельзя менять личные списки пользователей, режим маршрутизации или выключать VPN через remote пакет.
- Не отправлять на сервер посещённые домены, ручные исключения или историю запросов пользователя.
- Если давно нет обновления, показывать ненавязчивое «Список правил может устареть» и кнопку проверки, но VPN продолжает работу.

## 6. Диагностика и правдивые состояния соединения

Главная кнопка не может писать «Защита активна» только потому, что значок VPN висит в шапке Android.

| Состояние | Человеческая надпись | Основание |
|---|---|---|
| OFF | Не подключено | VPN выключен |
| CONNECTING | Подключаемся | Инициализация Xray/разрешение Android |
| WAITING_NETWORK | Ожидаем интернет | Нет работающего физического подключения; VPN Service может оставаться поднятым |
| CHECKING | Проверяем защиту | Туннель поднят, контрольный запрос ещё не прошёл |
| CONNECTED | Защита активна | Есть VPN и подтверждённый выход через ожидаемый proxy-маршрут |
| DEGRADED | Подключение работает с ограничениями | Работает только часть проверок (VPN/DNS/direct) |
| RECONNECTING | Восстанавливаем соединение | Туннель/сеть перестраивается |
| EXPIRED | Подписка закончилась | Серверный срок истёк |
| ERROR | Не удалось подключиться | Повторяемая ошибка с понятным действием |

Реализовать проверку NetworkCapabilities и событий ConnectivityManager, а затем адресные проверки реального маршрута. VPN-значок сам по себе не доказывает работу сервера. Не увеличивать расход батареи секундным polling; инициировать проверку на событиях сети, старте соединения и по требованию, использовать разумную редкую фоновую проверку.

Кнопка «Проверить подключение» показывает результаты:
физический Wi-Fi/сеть; состояние Xray; DNS; проверочный ресурс через VPN; проверочный ресурс напрямую; Telegram. Каждый пункт сопровождается действием «Повторить», «Проверить Wi-Fi», «Обновить подписку», «Открыть настройки Android», «Написать в поддержку». Если нельзя доказать маршрут — писать «Не удалось определить», не выдумывать.

Отчёт диагностики пользователь копирует **только по желанию**. Не помещать в него Bearer/QR/URL подписки, адреса открытых пользователем сайтов, личные доменные исключения и другие секреты. Контрольные запросы используют публичные тестовые endpoints без журналирования истории сайтов. При падении VPN не нарушать пользовательский пункт «Всегда через VPN» тихим переходом напрямую.

## 7. Остаток подписки на главной странице

Небольшая карточка под кругом VPN, с переходом по нажатию в Telegram Mini App:

- «Активна · 24 дня», дата конца по локальному времени; предупреждение за **3 дня**.
- «Пробный доступ · 09:32» (обратный отсчёт до серверного deadline); мягкое предупреждение за 2 минуты.
- «Нет подписки» + понятная кнопка «Оформить»; новому пользователю сначала 15 минут пробного доступа.
- «Истекла», «Приостановлена», «Не удалось проверить» — отдельные состояния, не маскировать как «Активна».
- При offline показать последнюю полученную дату с пометкой «Последняя проверка…». Она не является доказательством действующего доступа.
- Источники: авторизованные GET /mobile/api/me и GET /mobile/api/trial/status; при необходимости — минимальный серверный endpoint для статуса/дедлайна, без раскрытия баланса, чужих устройств и URL подписки.
- Срок исчисляется из UTC epoch сервера с учётом локальной зоны для отображения. «0 дней» при нескольких оставшихся часах ≠ «Истекла». Простое изменение системных часов не продлевает доступ.
- Синхронизация после оплаты через Mini App, reboot, потери сети и обновления приложения без повторной привязки.

## 8. Проверка первого запуска без риска для аккаунта SOFIX

**A. Демо на уже привязанном устройстве.**
Скрытая активация в меню для разработчика (например, семь нажатий на номер версии + явное подтверждение). Демо реализуется только как отдельная локальная модель экранов, с постоянной надписью **«ДЕМО — реальный VPN, аккаунт и деньги не меняются»**. Нельзя вызывать API выдачи 15-минутного ключа, менять токены, оплачивать, создавать Telegram-аккаунты, занимать один из трёх слотов или переключать работающий VPN. Можно многократно воспроизвести весь интерфейс: красная кнопка → предложение 15 минут → имитация этапов подключения → имитация Telegram → объяснение следующего шага. «Имитация успешно» не должна выглядеть как реальная проверка интернета. Выход из демо возвращает истинное состояние без повторного подключения.

**B. Настоящий E2E регистрации.**
Отдельный ранее не зарегистрированный Telegram-аккаунт и чистый Android-профиль / отдельный тестовый телефон, желательно отдельный staging VPN и staging API. Там реально проверить выдачу пробника, разрешение Android VPN, доступность Telegram, создание аккаунта и привязку устройства без шестизначного кода. Настоящую проверку нельзя заменить демо-экраном. Не удалять и не трогать токены/подписку @sofix_repair.

**Техническое ограничение:** если до активации VPN нет доступа к API SOFIX, пробник нельзя получить. В 0.8 сделать честное сообщение и повтор, а не изображать выданный VPN. Offline bootstrap/дополнительные каналы подключения потребуют отдельного решения.

## 10. Порядок реализации и стоп-факторы

1. Спецификация правил + чистый модуль разрешения маршрутов; unit tests без компиляции APK.
2. Генерация Xray-конфига из SOFIX rules; проверка DNS/IPv6/приоритетов и rollback.
3. Формат обновления списков, подпись и staging-публикация; отрицательные security tests.
4. Нативный экран режимов и исключений + локальная проверка маршрута сайта.
5. Состояния VPN/сети и реальная диагностика, включая батарею и офлайн.
6. Синхронизация статуса подписки из существующих авторизованных API.
7. Изолированное локальное демо и реальный E2E на отдельном профиле.
8. Совместные автоматизированные тесты, затем одна Android QA-сборка и регрессия на OPPO A54 5G; при необходимости второй аппарат Tecno Pova 7 Neo.
9. Только после приёмки: release-notes, CHANGELOG, GPLv3-исходники, SHA-256, постоянная подпись и релиз 0.8 Beta.

**Блокируют выпуск:** утечки DNS/токенов, нарушение «Всегда через VPN», стирание ручных правил, silent fail-open, поломка рабочих подписок/автообновлений/автозапуска, невозможность отката, демо с реальными изменениями данных.

## 11. Зафиксированные решения

- По умолчанию Smart; **всё неизвестное публичное → VPN**.
- Российские ресурсы напрямую только после исключения известных ограничений и пользовательских переопределений; не включаем безусловный geoip:ru → direct.
- Ручные исключения выше автоматических, более точный домен выше родительского, идентичный конфликт требует выбора пользователя.
- DNS, IPv6, Android VpnService, NAT64, QUIC — входят в 0.8 как технические обязательства.
- Правила доменов обновляются отдельно от APK, с подписью и last-known-good.
- Срок подписки от сервера, не из предполагаемых локальных данных.
- Demo не равно реальной активации; production аккаунт @sofix_repair не трогаем.
- В рамках текущего запроса — **только документация, без APK, release/tag или изменений боевых сервисов**.

**Готовность 0.8:** новый пользователь получает понятную VPN-кнопку, работающий Smart и остаток подписки; ошибочный маршрут исправляется за считанные нажатия; обновления правил безопасны; диагностика сообщает реальные проблемы; тест первого запуска не ломает настоящий аккаунт; все сценарии R/U/D/Q подтверждены автоматическими и Android-тестами.
